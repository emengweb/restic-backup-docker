# Configuration and compatibility contract

One shared runner/codebase serves all labels. The default all-in-one image contains files, PostgreSQL16/17 and MariaDB11.8; the only other image is opt-in lite, which contains no database tools. Database/version-specific labels are not built or published. Image capability metadata rejects incorrect engine or restore-server configuration before exporting. Existing per-project repositories remain unchanged. Restore never filters by Pod/node/host; auto latest is ordered by snapshot timestamp after dataset/format compatibility. No manual snapshot ID is required. Dataset defaults to hashed repository endpoint/bucket/prefix for one-project-per-repo legacy deployments; set DATASET_ID for shared repos or to preserve identity if URI changes, not controller UID. REPOSITORY_ISOLATED=false requires DATASET_ID.

DATABASE_TYPE empty/files, pg/postgres/postgresql, mysql/mariadb aliases; DATABASE_HOST/PORT/USER/NAME/PASSWORD and corresponding PG_*/POSTGRES_*/MYSQL_*/MARIADB_* aliases. DATABASE_NAME comma-list explicitly declares all databases. *_PASSWORD_FILE reads mounted Secret, no values logged. DATABASE_MAJOR (or RESTORE_TARGET_MAJOR/TARGET_DATABASE_MAJOR) sets restore target; no automatic PG major migration. Physical pg_basebackup mode uses BACKUP_MODE=physical with streamed WAL and native validation; BACKUP_MODE=dual runs both native streams under the original schedule/window and records success only if both complete. Physical mode requires source replication permissions. Logical is the default for compatibility until native physical permissions/restore are accepted. MariaDB helpers in this initial image support target11.8; a source11.5 requires explicit target11.8 for logical migration and is not safe to hand back to an unchanged11.5 main image. Native MariaDB physical mode is not implemented and returns an explicit error, not a raw-file-copy fake success. Engine restores require server helper and extensions/locales in the one image.

Keep BACKUP_CRON/CHECK_CRON/PRUNE_CRON and DATABASE_BACKUP_TIME=HH-HH/TZ per project. Cross-midnight windows allowed. No forced */30 or forced startup export. Outside DB window a job is skipped with exported=false, never a fresh database success; files mode unaffected. Window-only skips must not declare real backup success.

DATA_PATH/RECOVERY_DATA_PATH default /data; BACKUP_WORK_PATH default /backup, on separate scratch. Source and scratch cannot contain each other. DB backup sidecar does not need PGDATA. File mode reads source directly via restic (does not copy entire volume into scratch); pre/post consistency hooks needed for app databases/SQLite/MinIO etc. File source can be read-only. Restore init mounts target read/write and separate scratch; use same image but command restore-init.

RESTIC_REPOSITORY/PASSWORD[_FILE], AWS_* credentials unchanged. Runner refuses automatic repository init or unlock on errors; provisioning a new repo is a separate operation. RESTIC_JOB_ARGS allows reviewed file-exclude/one-filesystem flags, not arbitrary shell. Hooks support /hooks, /custom and legacy /custem; use HOOKS_DIR if more than one path defines the same hook. Hook subprocess rc is propagated; no automatic npm install. Legacy mail/Teams forwarding of full logs is deliberately not preserved (may leak credentials); attach external sanitized alerting to structured status. NFS mount must be provisioned by Kubernetes rather than privileged mount on startup; unsupported legacy options must be explicitly reviewed.

JOB_TIMEOUT_SECONDS=900, BACKUP_MAX_BYTES default2Gi, BACKUP_MIN_FREE_BYTES default256Mi; per-target capacity/budgets must be configured before rollout. RESTORE_MAX_AGE_SECONDS default7days (0 disables age guard); RESTORE_MAX_CANDIDATES=5; RESTORE_FALLBACK=true allows older compatible verified candidate with reported snapshot_time/fallback_count. Authentication, space, storage I/O and ownership failures do not silently select stale data.

Legacy file /data snapshots accepted in isolated repos (RESTORE_LEGACY). Legacy PG/MariaDB physical datadir requires RESTORE_LEGACY_PHYSICAL=true and native compatibility validation, never implied safe merely from the path. Existing custom native PG archives (including Affine) use a generic strict legacy adapter: matching LEGACY_NATIVE_PATHS (default /backup/export/current), checksum-covered PGDMP custom files and globals, full decode/header validation, and LEGACY_DATABASE_METADATA_FILE with exact declared locale/extension versions/owner when missing creation TOC. No host identity is needed and incomplete handwritten SQL is not accepted as native. Do not treat a PG14 data folder as PG17 or handwritten SQL as complete native backup.

Whole repo check preserves RESTIC_DATA_SUBSET, CHECK_READ_ALL_DATA selects full read-data. AUTO_REPAIR_INDEX requires MAINTENANCE_EXCLUSIVE and REPAIR_ROLLBACK_AVAILABLE gates; index reconstruction is not missing-data repair. No automatic repair snapshots/packs, --remove-all unlock or init.

prune defaults dry-run; --apply requires RETENTION_APPLY, MAINTENANCE_EXCLUSIVE and a persisted RETENTION_PROOF_FILE containing schema_version=1, matching repository_identity, stable_since/observed_until at least7days apart, recent observed_until, unresolved_failures=0 and restore_verified entries naming existing newest snapshots verified within24h. Boolean RECENT_RESTORE_VERIFIED or old date env alone never authorizes cleanup. All maintenance retains at least7days and one snapshot per stream. Existing RESTIC_FORGET_ARGS keep policies are parsed as values only, never shell. Group paths,tags not dynamic host; keep-last>=1 per stream and preserve legacy until observation accepted. check/prune are whole repo operations. Shared local flock only serializes one local runner; native Restic repo locks serialize individual remote commands. External single writer/fencing policy required across Pods/nodes/repair-retention sequences; a Lease without source-node fencing cannot promise split-brain safety.

Backup health is a separate metric/status, not DB Pod readiness. Existing DB Service may not publish NotReady endpoints; using localhost for same-Pod export avoids bootstrap deadlock. Node failure does not magically relocate local-path PVC bound to old node: storage/controller must create an eligible empty target for init to run. Do not delete old PVC/data automatically.
